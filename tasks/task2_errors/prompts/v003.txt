Definitions:
- "Lỗi biên dịch": a real syntax or type error that stops compilation (missing semicolon or brace, undeclared variable, wrong return statement, misspelled keyword). Code written for MSVC ("void main", pow without <cmath>) is NOT a compile error. In multi_problem exams students submit only functions, so a missing main() is NOT a compile error.
- "Lỗi nhập/xuất": input read wrongly or output not in the required format (wrong words or case such as TRUE instead of True, extra spaces, extra prompts like "Nhap n:", missing values, wrong file reading).
- "Lỗi logic": a wrong condition, formula or branch inside an otherwise reasonable approach, so some results are wrong.
- "Lỗi vòng lặp": a loop bound, start, update or stop condition is wrong (off-by-one, skipped element, a loop variable that is never updated causing an infinite loop).
- "Lỗi mảng/chuỗi": wrong index, out-of-bounds access, wrong string/array handling, returning a pointer to a local array.
- "Lỗi hàm": wrong function definition or use: wrong parameters or return type, missing return value, wrong call, conversion functions misused (stoi/stof on invalid text).
- "Lỗi edge case": the main cases work but boundary inputs fail (smallest/largest values, empty input, single element, all equal, negative numbers).
- "Lỗi thuật toán": the overall method is wrong or cannot solve the problem, or it is far too slow for the constraints.
- "Lỗi hard-code": fixed values that should come from input or data (hard-coded file name, array size, number of records, expected outputs).
- "Lỗi style": poor naming, messy structure, large commented-out code, or forbidden library use without a functional error.

Rules:
- Assign a label only when you can point to the code that causes it. Verify a suspected bug by tracing an example input before assigning it; for example, a loop that increments its variable every iteration is not an infinite loop.
- Most submissions have 0, 1 or 2 labels. A fully correct submission has an empty list.
- If the code does not compile, include "Lỗi biên dịch" and add another label only if that error is also clearly present.
- Prefer "Lỗi logic" for a local mistake and "Lỗi thuật toán" only when the whole approach is wrong.
